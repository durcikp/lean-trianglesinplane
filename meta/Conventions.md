# Formalization conventions (shared by all contributors)

Read `automation/Instructions.md` first; this file records the concrete Lean design choices.
The manuscript is `blueprint/triangles_in_the_plane_blueprint.tex` (the "blueprint").

## Project layout
- Lean project root: this repository (`lakefile.toml`, Mathlib `v4.33.0-rc2`).
- All Lean code lives in `Auto/`, in the single namespace `Auto` (`namespace Auto ... end Auto`).
- One folder per blueprint section (CamelCase title, articles and "and" omitted), one file per leaf
  subsection. Material before the first subsection of a section goes in its own file named after
  the section.
- Every Lean file starts with the header required by the autoformalize skill:
  `/- Copyright (c) 2026 Polona Durcik. All rights reserved.` / `Released under Apache 2.0 license as
  described in the file LICENSE.` / `This file was automatically generated by Claude.` / `-/`.
- Root module `Auto.lean` imports every non-scratch file. Scratch files go in `Auto/Scratch/` and
  are never imported; delete them when done.
- Check a file with `lake env lean <file>` (builds nothing; imported modules must already be built
  with `lake build Auto.Folder.File`). This Lake has no `-j` flag. Machine: 16 GB RAM, so at most
  3 concurrent Lean-heavy agents.
- `lake env lean` does not apply lakefile options: put `set_option maxSynthPendingDepth 3` in scratch
  files if instance synthesis fails.
- In this Mathlib, `ContDiff ℝ ⊤` means analytic; use `ContDiff ℝ (⊤ : ℕ∞)` for `C^∞`.

## Core objects (in Section 4's file)
- Plane: `ℝ²` is scoped notation for `EuclideanSpace ℝ (Fin 2)`. Coordinates `x 0, x 1`.
- Angles: `Ang = AddCircle (2 * π)`; `u θ`, `v θ = J (u θ)`; probability arclength `σ : Measure Ang`.
- `J`, `simil a b = a•I + b•J`, `M α β = simil α β`, `rot t`, `Lv α β : Fin 3 → (ℝ² →L[ℝ] ℝ²)`
  = `(0, I, M)`, `e1`. The triangle parameters are explicit arguments `(α β : ℝ)` with `(hβ : β ≠ 0)`.
  `Mᵀ` is written `ContinuousLinearMap.adjoint (M α β)` in statements.
- Configuration space `ℝ² × Ang`, `μinc = volume.prod σ`, `proj α β j p = p.1 + Lv α β j (u p.2)`.
- **Finite complex measures** on `ℝ²`: `FCMeasure` = pushforward `φ_*(w·m)` of an `L¹(m)` complex
  density `w` on an auxiliary s-finite measure space `(Z, m)`; `ν.integral g = ∫ g(φ z) w z dm`,
  `ν.tv = ∫⁻ |w| dm` (= ‖ν‖_TV for the polar presentation, ≥ it in general; statements quantify over
  all presentations so this is faithful), `ν.varOn A` (= |ν|(A)), `ν.fourier`.
  Constructors: `FCMeasure.ofMeasure μ`, `ofDensity k` (L¹ density), `dirac a`, `sigma` (σ on the
  unit circle), `dil s ν` (= ν_s, pushforward by u ↦ su), `smul c ν`, `add`, `sub`,
  `conv ν κ` (= ν * κ), `convFun κ f` (= κ * f).
- Counting form `form α β ν f₀ f₁ f₂ = ∫ (∫ f₀ x f₁(x+φ z) f₂(x+M φ z) dx) w z dm(z)`.
  Endpoint norm `endNorm α β ν i : ℝ≥0∞` (bounded slot `i`), `formNorm α β ν = endNorm α β ν 2`.
  `aux_slotExp i j` is `∞` if `j = i`, else `2`.
- `e t = exp(2πit)`, `scaleR R h u = R² h(Ru)` (`h_R`).
- Fourier transform: Mathlib's `𝓕`/`𝓕⁻` (same convention as the blueprint).
- Norms: use `eLpNorm f p` (values in `ℝ≥0∞`); prefer stating inequalities in `ℝ≥0∞` (`‖z‖ₑ`, `∫⁻`).
- Operators are raw maps `(ℝ² → ℂ) → (ℝ² → ℂ)`; where genuine Hilbert-space theory is needed
  (compactness, adjoints, kernels) use Mathlib's `Lp ℂ 2` and `→L[ℂ]` and relate them to the raw
  maps (`T f =ᵐ rawOp f`). Compactness is Mathlib's `IsCompactOperator`.

## Statement style
- Every blueprint theorem/lemma/proposition/corollary is a Lean `theorem`, named after its label
  with `:` and `-` replaced by `_` (e.g. `rig:kernel-gap` ↦ `rig_kernel_gap`); a split into several
  theorems uses suffixes with matching docstrings.
- Docstring of the formalizing theorem: `**Lemma `label`** (part).` followed by the copied LaTeX
  statement only (doc-gen4 renders `$...$`, `$$...$$`).
- Definitions: docstring may copy the LaTeX definition and must name its label.
- Explicit numerical constants: `def C_<theorem name> := ...`. Unspecified constants are
  existentially quantified after the parameters they depend on.
- Auxiliary material is prefixed `aux_` and its docstring says what it is for.
- Mathlib's `#lint` exceptions are intentional and marked with `@[nolint ...]`:
  `defsWithUnderscore` on `aux_` definitions and `C_<theorem name>` constants (naming required by
  `automation/Instructions.md`), and `unusedArguments` on public theorems whose manuscript hypotheses
  the proof does not need (these also carry `set_option linter.unusedVariables false in` with a
  comment). Unused arguments of `aux_` lemmas are removed instead.
- Add only hypotheses needed for faithful semantics (measurability, `MemLp`, finiteness).
- Only mark `Proof completed` when `#print axioms` shows just `propext`, `Classical.choice`,
  `Quot.sound`.
